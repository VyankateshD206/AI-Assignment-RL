01 / FORMULATION

A practical problem, defined as an MDP.

STATE · ACTION · REWARD

Two rooms have different heat exposure and class schedules. During a shared power restriction, only one AC may fit. Can a policy anticipate classes and keep both rooms comfortable without wasting energy?

Environment

A day is divided into decision intervals. Outdoor air, sunlight and occupants add heat; AC removes it. Room 1 has more solar gain and less thermal inertia.

T′ = T + Δt / C × (outdoor + solar
                  + occupants + fan − AC)

A fan adds motor heat. Its assumed airflow benefit is represented separately in the comfort proxy.

MDP observation · 17 features

  • Both room temperatures and current occupancy
  • Next class time and expected occupancy per room
  • Outdoor temperature, solar input and cyclical time
  • Current / next power cap and time to change
  • Previous AC states

DQN derives comfort features from these scaled inputs. Q-learning uses a smaller, approximate subset of temperature, occupancy, class-soon, power and previous-AC bins. The observation summarizes the day and is an approximate MDP state.

Action · 16 joint combinations

Room modeACFan
0OffOff
1OffOn
2OnOff
3OnOn

a = 4 × room_1_mode + room_2_mode

Actions above the power cap are masked during selection and learning targets.

Reward · four penalties

r = −(wE × energy + wD × discomfort
      + wF × worst room + wS × switching)

Discomfort is squared deviation outside the comfort band, weighted by occupancy. Empty rooms have no discomfort penalty. AC state changes are penalized.

The worst-room term encourages fair allocation; it does not guarantee long-term equality.

Model parameters and assumptions

Loaded from Python configuration. No real-building calibration, humidity, ventilation or compressor minimum run times. The fan offset is an assumed proxy, not a validated comfort model.

Edit a JSON config and restart with python gui.py --config configs/custom.json --models for baseline exploration. Changed physical configurations require matching trained checkpoints. Changing reward weights alone does not retrain a policy.

Presentation note “We define the state, action, transition and reward first. Then we learn a policy and compare it with rules on the same environment.”

02 / LEARNING

Learn from experience. Explain the policy.

Q-LEARNING + DQN

The agent tries cooling actions during training. Rewards improve its action-value estimates over many simulated days. Evaluation then freezes the learned policy.

REPEATED DURING TRAINING

One interaction becomes learning experience

Agent ↔ environment
  1. 01ObserveRead the classroom state
  2. 02ChooseExplore or use Q-values
  3. 03SimulateRun a feasible action
  4. 04ScoreReceive the reward
  5. 05UpdateImprove value estimates

During evaluation, steps 1–4 use a frozen policy. The update step happens only in training.

Q-learning · a table of action values

Q(s,a) ← Q(s,a) + α [target − Q(s,a)]
target = r + γ max Q(s′, feasible a′)

Bin the state, explore feasible actions with ε-greedy, and update one table entry per transition. Unvisited states have zero values; sparse coverage can lead to poor behavior.

DQN · approximate the same values

17 raw observations → comfort features
21 inputs → 64 ReLU → 64 ReLU → 16 Q-values
replay → minibatch → Huber loss → Adam

Store experience, sample past transitions, and fit a neural Q-function. A target network stabilizes targets. Both algorithms use zero bootstrap at day-end.

How to train and change parameters
python train.py --algo q_learning --episodes 1500 --seed 0 --output outputs/q_new
python train.py --algo dqn --episodes 400 --seed 0 --output outputs/dqn_new
python train.py --algo dqn --config configs/custom.json --episodes 300 --seed 0 --output outputs/dqn_custom

Use fresh output directories. Physical parameters and reward weights are JSON fields. The training CLI exposes learning rate, discount, exploration, batch size, replay warmup, target interval and update frequency. Network architecture and replay capacity require source changes. Train again after changing the learning task or objective, then restart the GUI to load the new policy.

--no-timetable removes explicit next-class inputs. --no-fairness removes the worst-room penalty. Use matching seeds to study each contribution.

Presentation note “Training changes the value estimates. Evaluation freezes them. We compare physical energy and comfort metrics, because changing reward weights changes the score.”

Arrival is measured before the class-start action. Early-class discomfort covers the first 15 minutes. All pre-cooling electricity is included in energy.

How these measurements work · timing and counts

Arrival uses air temperature minus the previously active fan’s configured offset; a newly selected action cannot change entry comfort. With five-minute decisions, early-class samples are at +5, +10 and +15 minutes. Whole-day comfort uses all occupied room-time. Empty rooms earn no comfort credit. Not applicable means there were no relevant arrivals or occupied minutes; unavailable means a trace lacks arrival measurements.

Prefer the upper left: less energy and more comfort. Point numbers match the table. A single day illustrates behaviour; use held-out days and independent training seeds for final claims.

Additional evaluation metrics

Power-cap violations are prevented by action masking. This is an enforced constraint, not learned safety.

Saved multi-day study · separate from this demo

Tuning helps select checkpoints; independent confirmation and final assessment test the frozen choice. A 50-day study means 5 scenarios × 10 synthetic days per policy. Rule-based controllers are comparison references; Q-learning and DQN are the RL solution.
